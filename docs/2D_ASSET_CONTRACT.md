# 日奈泳装 2D 资产交付合同

> 适用阶段：M3 及以后
> 当前状态：运行时使用程序化占位角色，正式日奈 2D 资产尚未选定来源

## 1. 目标

正式资产需要能被桌宠渲染器直接加载，并支持待机、视线、走动、睡觉、点击、抚摸、拖拽和表情切换。

当前默认路线是“分层 PNG/WebP + 渲染器变换”。如果后续获得完整 Spine 或 Live2D 工程，可以通过新增 Renderer Adapter 接入，行为规则和存档不需要重写。

## 2. 画布与锚点

- 设计画布：`340 × 460` CSS 像素。
- 建议交付分辨率：`680 × 920`，即 2 倍素材。
- 透明背景。
- 角色脚底锚点：约 `(170, 420)`。
- 角色顶部需要容纳光环、角和头发，不裁切。
- 角色主体应保持在安全边距内，方便左右走动时镜像。

画布尺寸以后可以由角色配置扩展，但同一套动作必须使用相同画布和锚点。

## 3. 点击区域

第一版命中区定义：

| ID           | 类型 | 位置                         |
| ------------ | ---- | ---------------------------- |
| `horn-left`  | 圆形 | 中心 `(144, 84)`，半径 `20`  |
| `horn-right` | 圆形 | 中心 `(196, 84)`，半径 `20`  |
| `halo`       | 圆形 | 中心 `(170, 55)`，半径 `43`  |
| `head`       | 圆形 | 中心 `(170, 148)`，半径 `64` |
| `body`       | 矩形 | `(116, 218)` 至 `(224, 372)` |

正式素材如改变位置，需要同步提供新的 `hitAreas` 元数据。

## 4. 必需动作

### 循环动作

- `idle`
- `walk`
- `sleep`

### 单次动作

- `wake`
- `tap_head`
- `tap_horn`
- `tap_halo`
- `tap_body`
- `headpat`
- `drag_start`
- `drag_end`
- `happy`
- `annoyed`
- `embarrassed`
- `surprised`
- `feed`
- `wave`
- `stretch`

### 运行时辅助

- `look_at_cursor`
- `drag_loop`

如果某个动作暂时缺失，渲染器会使用 `ACTION_FALLBACKS` 回退到 `idle`、`happy` 或 `annoyed`，不会导致应用崩溃。

## 5. 表情

至少需要：

- `neutral`
- `happy`
- `annoyed`
- `embarrassed`
- `sleepy`
- `surprised`

表情可以与身体动作组合。例如 `headpat + embarrassed`、`wave + neutral`。

## 6. 帧动画交付格式

每个动作单独目录：

```text
actions/
  idle/
    frame_000.webp
    frame_001.webp
  tap_head/
    frame_000.webp
    frame_001.webp
```

同时提供 `actions.json` 或等价清单，说明：

- 帧率和总帧数
- 是否循环
- 循环起止帧
- 动作结束后的默认动作
- 是否允许水平镜像

推荐帧率：12～24 FPS。低帧率手绘动画比高频程序插值更符合二次元角色。

## 7. Spine 交付

需要：

- Skeleton 数据文件
- Atlas 文件
- 全套纹理
- 每个必需动作的 Animation 名称
- 表情/参数映射
- 运行库版本与授权说明

动作名应直接使用本文档中的统一动作 ID，避免在应用内维护第二套命名。

## 8. Live2D 交付

需要：

- `.model3.json`
- `.moc3`
- 纹理
- motions
- expressions
- physics
- 参数映射
- 运行库版本与授权说明

至少需要提供头部角度、眼球位置、眨眼、嘴型和基础情绪参数。

## 9. 图片与版权

- 正式素材放入 `assets/characters/hina-swimsuit/private/`。
- `private/` 已被 `.gitignore` 排除。
- 仓库只提交占位素材、清单和接入代码。
- 公开分发前必须确认角色、立绘、模型、动画和运行库授权。

## 10. 当前待决定事项

正式 2D 形象需要在以下路线中选择：

1. 自制或委托绘制分层 PNG 帧动画。
2. 使用 Spine 工程获得更平滑的角色动画。
3. 使用 Live2D 工程获得更完整的视线和面部控制。
4. 先继续使用程序化占位角色，直到玩法与设置稳定后再投入正式美术。

在素材路线确定前，M3 的运行时、自动行为、命中区、动作回退和设置入口仍可独立开发与验收。
