# 日奈桌面情境 AI V1

> 更新日期：2026-10-25  
> 状态：DeepSeek 云 API、受约束主动 AI、场景陪伴与低延迟本地语音已接入

## 1. 范围

V1 只实现四类信息：

1. 前台应用类别：`browser`、`focus`、`development`、`communication`、`media`、`desktop`、`other`。
2. 本地时间、时段、周末状态。
3. 可选窗口标题，默认关闭。
4. 可选选中文字，只在用户主动触发时读取。

不读取屏幕截图、不轮询剪贴板、不读取输入内容、不自动执行应用操作。

## 2. 主动场景陪伴

本次新增纯本地 `SceneCompanion`：

- 新场景至少稳定 20 秒后才允许触发。
- 两次主动场景对白采用约 70～180 秒的随机间隔，不做固定周期播报。
- 用户最近 30 秒有互动时暂停主动场景台词。
- 系统空闲超过 120 秒时暂停。
- 锁屏、睡眠、完全穿透、拖拽中、系统应用场景均不触发。
- 共 27 条候选表现，根据场景、时段、精力、心情和好感等级筛选。
- 最近 10 次表现不会重复；候选耗尽后才会重新轮换。
- 官方日语片段和日奈生产声线的预生成 WAV 都会参与选择，动作覆盖待机、视线、挥手、伸展、开心、困倦和官方模型动作。

主动场景对白使用官方日语片段或 `content/prebuilt-tts-ja.json` 中随应用打包的 WAV。固定台词即使带有空的情绪参数，也必须优先命中预生成音频。文字先显示，音频直接从本地读取，不启动 Irodori 服务。

当精力不足且抽中休息类表现时，会按 `content/affection.json` 的 `idleRecovery` 配置分阶段恢复精力和心情。该恢复有 120 秒冷却，不增加好感经验。

## 2.1 受约束的主动 AI

M5.5 在本地 `SceneCompanion` 与 Presence 仲裁之上增加可选主动规划，默认关闭：

```text
本地高价值候选（priority >= 40 且有台词）
→ 每小时预算与开关检查
→ 只发送受控场景/情绪/关系/记忆摘要
→ DeepSeek 返回结构化表演计划
→ 白名单校验
→ 采用台词、只做动作或选择沉默
```

- 必须同时开启“启用 DeepSeek”和“允许日奈主动规划”。
- 默认每小时最多 4 次；普通微动作、自主行走和低优先级场景评论不会触发云端请求。
- 主动上下文不包含窗口标题、前台应用名称、选中文字或正文。
- 最多提供 5 条结构化记忆摘要；模型引用未提供的记忆 ID 时会被过滤。
- `should_speak=false` 时可以不发言，也可以安静地做一个动作。
- 请求失败、超时、无 Key 或响应非法时回退本地固定台词。
- 点击、场景/时段切换、锁屏、睡眠、隐藏、完全穿透、设置关闭和退出会取消未完成请求，晚到结果直接丢弃。
- 设置页会显示本小时请求数、预算和最近结果，便于验收主动 AI 是否真正被调用。

## 3. 用户触发的 DeepSeek

快捷键：

```text
分析当前任务：⌘⌥⇧D
解释选中文字：⌘⌥⇧S
```

托盘与角色右键菜单同样提供“让日奈看看…”入口。

流程：

```text
用户触发
→ 读取已批准上下文
→ 设置页显示逐字预览
→ 用户点击“发送给日奈”
→ 主进程请求 DeepSeek
→ 校验 JSON
→ 中文气泡立即显示
→ 日文台词按情绪走本地 TTS
```

云端请求只在预览确认后发生。

## 3.1 动作、语音与打断协调

M5.6 将动作和语音生命周期统一到 performance token：

```text
idle → preparing → performing → recovering → idle
```

- 表情先到位，主动作在 70 ms 后启动；低功耗模式取消预备延迟。
- 主动语音播放期间，普通 replace 动作会被拒绝；只有视线、呼吸和头发等 overlay 微动作可以叠加。
- 用户点击或拖拽会立即中断旧语音和旧动作，旧句不会继续播放。
- 单次动作完成后进入明确恢复阶段，再回到 neutral 待机。
- 同一 ambient clip 在 5 分钟内连续请求时会降级为微动作。
- 环境动作不会重置低功耗计时，因此待机和主动陪伴不会让电池模式一直保持 60 FPS。
- 当前情绪会决定本地 TTS 的语速和 seed；疲劳更慢，高激活与不耐烦风格更短促。

## 3.2 Presence v1 最终策略

- 默认强度为“平衡”，可切换“克制”“活泼”。
- 用户可关闭“允许日奈主动行动”；关闭后仅保留直接互动和用户主动 AI。
- 三档预算、静默条件和防重复边界见 `docs/PRESENCE_RELEASE_POLICY.md`。
- `npm run presence:replay` 使用虚拟时钟执行 8/24 小时场景，并输出预算、重复率和打断率报告。
- 设置页实时显示内存中的 Presence 遥测，不持续写事件日志。

## 4. DeepSeek 配置

```text
endpoint: https://api.deepseek.com/chat/completions
model: deepseek-chat
temperature: 0.6
max_tokens: 220
stream: false
response_format: json_object
```

返回结构：

```json
{
  "reply_zh": "中文气泡",
  "reply_ja": "日文语音台词",
  "emotion": "calm",
  "action": "look_at_cursor",
  "confidence": 0.82
}
```

`emotion` 与 `action` 都使用白名单。模型不能直接指定任意动画、文件或终端操作。

## 5. 隐私与权限

- API Key 通过 Electron 异步 `safeStorage` 加密，文件位于应用数据目录，权限为 `0600`；旧同步密文会兼容迁移为 Schema 2。
- 渲染进程不能读取已保存的 Key。
- 窗口标题默认关闭。
- 选中文字权限默认关闭，只在每次主动触发时读取。
- Obsidian、部分 Electron 编辑器或网页输入框不会暴露 `AXSelectedText`。此时会进入安全的手动粘贴模式：预览框变为可编辑，由用户主动从目标应用复制后粘贴。
- 手动粘贴模式不读取或轮询系统剪贴板，不模拟 `⌘C`，也不会覆盖用户当前剪贴板。
- 窗口标题与选中文字需要 macOS 辅助功能权限。
- `NSAppleEventsUsageDescription` 只在用户主动触发的上下文中使用。
- 待发送上下文只在主进程内存保存 120 秒；取消、关闭或成功发送后立即清除。
- 不保存 DeepSeek 回复正文、请求正文或聊天历史。
- 选中文字最多 4000 字，窗口标题最多 160 字。
- 手动粘贴的文字同样只保存在设置页，并在用户点击“发送给日奈”时随本次请求发送。

## 6. 延迟策略

- 现有 40 条固定中文对白及 1 条 AI 等待应答预生成并随应用打包。
- 命中固定对白时不启动 TTS 服务，直接从本地 WAV 返回。
- 场景主动对白全部来自固定对白池。
- DeepSeek 启用后只预加载 TTS 模型，不预生成未知 AI 台词。
- DeepSeek 请求期间立即显示“让我看一下”气泡，避免界面无反馈。
- 用户确认 AI 请求后，DeepSeek 请求与 Irodori 模型预热并行执行。
- 确认请求后立即播放 1.28 秒的预生成“……嗯。”，填补云端与首段语音之间的空白。
- 云端文本返回后先显示中文气泡，再把日文回复按标点拆成短段。
- 动态语音使用 24 步采样；第一段完成后立即播放，其余段在播放期间继续合成。
- 同一个云端回复的各语音段复用确定性 seed，降低分段之间的音色波动。
- DeepSeek 回复限制为约 70 字、通常 1～2 句，减少无意义的长时间朗读。

## 7. 验收

- DeepSeek client 单元测试覆盖成功、非法动作、401、JSON 解析与长度限制。
- API Key 测试确认磁盘不含明文，且安全存储不可用时拒绝落盘。
- 场景陪伴测试覆盖稳定窗口、冷却、切场景和隐私抑制。
- 固定对白测试保证 `tts-ja.json` 中每条对白都有打包 WAV。
- Electron E2E 覆盖设置页 AI 面板、原有互动、渲染与资源治理。
- Electron E2E 将前台应用设为 `Visual Studio Code`，确认自动触发开发场景对白。
- 该场景语音来源必须为 `official` 或 `prebuilt-tts`，同时 Irodori 状态保持 `unloaded` 且没有 PID。
- 电池低功耗转换连续重复测试 3 次通过，避免计时边界偶尔停留在 `active`。
- 长日文 AI 回复的 E2E 测试验证拆分为多段，并记录首段开始播放时间。
- E2E 验证系统无法读取选区时会显示“选中文字 · 手动粘贴”、文本框可编辑，且只有粘贴非空内容后才允许发送。
